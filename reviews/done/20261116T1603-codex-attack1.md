## 1. Reach: don't build the graph; decode each reference when the flood reaches it, from columns

**Problem.** Reach (2): the live set from the roots, over relocations plus the method rules.

**Before.** Two shapes. hlink floods straight over the raw objects, decoding each live symbol's relocation records
((package index, symbol index) -> canonical id) on the spot: 98-103 ms on 1 core, 22-23 ms on 8 (MinIO). The textbook
data-parallel shape, and what the flat files hand every paradigm, is "decode everything into a canonical CSR, then
flood": the flood alone is fast (p2par 26-30 / 8.6-17 ms), which made it look as if the flat layout had won.

**Observation.** It hadn't: the flood reads only **28.7%** of the CSR's edges on MinIO (2.39 M of 8.32 M) and **21.0%**
on kube-apiserver (3.27 M of 15.6 M), and a quarter of those repeat a (source, target) pair
(`python3 ref/flat/reachfacts.py data/<dataset>`). Building the graph is 3.5-5x more decoding than reach needs, and
measured end to end (Codex, `ref/flat/p2pipe.c`: decode 9.4 M targets + count/prefix/fill + flood) it loses:
**108.7 ms on 1 thread, 30.1 ms on 8** on MinIO (results/codex-d.md; my rerun 16:04Z: 33.7 ms on 8), slower than hlink.
The CSR build alone (11.7 ms on 8) costs as much as the flood.

**Attack.** Keep the relocations as columns (`rel_pkg`, `rel_idx`, `rel_type`, one contiguous range per symbol,
`slot_rel`) and decode inside the flood: when a symbol becomes live, walk its range, map (pkg, idx) through its
object's package-base table and the canon array, mark. That is hlink's lazy shape on a columnar layout, parallel
by level (`ref/flat/p2lazy.c`, the flood loop of p2par with ~15 lines changed).

**Number.** MinIO: **52.6-53.3 ms on 1 thread, 13.6-15.4 ms on 8** (P2 OK; 16:02-16:04Z, load 0.8, interleaved with
p2par). kube-apiserver: 72.7 / 19.9 ms. vs the eager pipeline 108.7 / 30.1 (2x) and hlink's raw-object flood
98-103 / 22-23 (1.9x / 1.5x).

**Caveats.** Both flat pipelines take the funcdata aux edges (704 K on MinIO), the interface kinds 1-3 and the
method tables precomputed from the p2 files, and the 1a canon from its oracle; hlink decodes those inside its
flood too, so the hlink ratio overstates the win by the cost of that work (dumpflat's untuned eager version of
all of it is 133-139 ms; a lazy one should be a fraction). The columnar relocation layout is what the extractor
produced, i.e. a cost hlink does not pay (it reads the object files in place); what the measurement shows is that
the *layout* of the references matters more than pre-decoding them.

**What it would take / next.** (a) Decode aux and the interface kinds lazily too, from columns, to make the hlink
comparison exact. (b) Dedup per source (25% of read edges). (c) Ask the paradigms: a lazy decode inside a flood is
a gather inside a fixpoint. Futhark/Halide want the edge list materialized (the eager shape that loses here);
Soufflé's rule `live(t) <- live(s), rel(s, r), target(r, t)` evaluated semi-naively is exactly the lazy shape,
if its join on `rel` runs over the columns rather than a B-tree. That is the kill test for each paradigm's P2 cell:
does it beat 108.7 / 30.1 ms (the eager pipeline) when its own input decode is counted?
# The flat files

Every system in the grid reads these and nothing else: no system parses Go objects. They are written by
`ref/flat/extract.sh <workload>` into `data/<workload>/` (git-ignored, about 1.1 GB for MinIO), by a copy of
bottom-up's hlink (`ref/hlink`, from bottom-up `774e37c`) with one added file, `ref/hlink/dumpflat.c`, that writes
hlink's own state at the phase boundaries. The link it dumps from is unchanged (its output is byte-identical to
the stock hlink's) and runs (`--version`).

`ref/flat/check.sh` builds three plain single-core C programs (`ref/flat/p1.c`, `p2.c`, `p3.c`) that read only
these files and reproduce every oracle exactly: that is the proof that the files say everything a problem needs.
Read them next to this file: they are the executable form of the rules below.

## Conventions

- Raw little-endian arrays, no header. The suffix is the element type: `.u8 .u16 .u32 .i32 .i64 .u64`;
  `.u64x2` is pairs of u64 (a 128-bit key: k1 then k2).
- `meta.txt`: `key value` lines (counts and a few addresses). MinIO: `nslots 5205427`, `nrel 9403582`, ...
- **Ids.** A symbol slot has a dense id `1..nslots` (0 is "none"). Ids above `nslots` (up to `nids-1`) are symbols
  the linker makes; they only appear in problem 3's address table. Per-slot arrays have `nslots+1` entries.
- **CSR.** `X_off.u32` / `X_start.u32` with `n+1` (or `nslots+2`) entries: the rows of item `i` are
  `[off[i], off[i+1])`.
- **Strings.** `P.off.u64` (count+1 offsets) and `P.bin` (bytes): string `i` is `bin[off[i]:off[i+1]]`.
  Strings are interned per table, so equal ids mean equal strings. String 0 is "".

## Common

| file | what |
|---|---|
| `slot_obj.u32` | per slot: its object (0..nobjs-1). Objects are in hlink's load order; an object's slots are contiguous |
| `name.off.u64`, `name.bin` | per slot: its symbol name (not interned; content-addressed symbols mostly have none). **Slot g's name is `name.bin[off[g-1] : off[g]]`** (off[0] = 0; there is no entry for slot 0), not `off[g]..off[g+1]` |

## Problem 1: resolve

Each object's slots are, in order: definitions referenced by package index (kind 1), content-addressed definitions
with a 64-bit hash (2) and with a longer hash (3), definitions by name (4), references by name to symbols defined
elsewhere (5).

| file | what |
|---|---|
| `p1_kind.u8` | per slot: 1..5 as above |
| `p1_namekey.u64x2` | per slot: the 128-bit key of (name, ABI) if the slot takes part in the join by name, else (0,0). (k1 is never 0 for a real key.) Kinds 4 and 5 take part; kind 1 slots with a key are *candidates* (below); static, unnamed and debug-info symbols have no key |
| `p1_rank.u32` | per definition (kinds 1, 4): its rank. bit 31: not DUPOK; bit 30: not DUPOK and has content (text symbols count as having content even with no bytes; DUPOK definitions never have bit 30); bit 29: a definition; bits 0-27: min(size, 2^28-1). References: 0 |
| `p1_flags.u8` | per slot: bit 0: the record says UsedInIface; bit 1: a reference made only by debug information |
| `p1_want.u64x2` | keys of names the linker itself looks up (builtins, `main.main`, the entry, `-X` names...): they take part in the join with value 0 and no slot |
| `p1_builtin.u64x2` | the key of builtin `i` (`nbuiltin` of them), for references with package index "builtin" |
| `slot_rel.u32` | CSR (`nslots+2`): the relocations of slot `g` are `[slot_rel[g], slot_rel[g+1])` (definitions only) |
| `rel_off.i32 rel_siz.u8 rel_type.u16 rel_add.i64` | per relocation: offset in the symbol, width, cmd/internal/objabi type (bit 15 = weak), addend |
| `rel_pkg.u32 rel_idx.u32` | per relocation: the target as the object names it: (package index, symbol index) |
| `obj_pkg_off.u32`, `obj_pkg.u32` | CSR per object: `npkg+5` bases. Entry `p < npkg`: the id base of that imported package (0xFFFFFFFF: not linked); then 5 entries for the special package indices Self, Builtin, Hashed, Hashed64, None (= 2147483643..2147483647): the base of this object's own block of that kind |
| `p1_hashkey.u64x2` | per content-addressed slot: kind 2: (the 8 bytes, the symbol's size); kind 3: (hash bytes 0-7, hash bytes 8-11) |
| `p1c_mark.u8` | per content-addressed slot: 1 if the flood (problem 2) reached it, in hlink's sense: any of live, pc-table, funcdata or name-needed was set on it (so 807,866 mark-1 slots are not in `oracle/p2_live.u32`; don't rebuild marks from the live set), 2 if it was not reached but a relocation the flood does not follow names it, else 0 |

**1a. The join by name.** Group the slots with a key (kinds 4 and 5) and the wanted keys by key. A kind-1 candidate
joins a group only if its key is already there (it never creates a group). The winner of a group is the maximum
of `rank << 32 | ~id` (highest rank, then lowest id); every member's canonical id is the winner. Every other slot
is its own canonical id, except a kind-5 slot with `p1_flags` bit 1, whose canonical id is 0. A group whose
winner is a reference stands for an undefined symbol. Builtin `i` resolves to its key's winner if that is a
definition (rank bit 29), else 0. Oracle: `oracle/p1_canon.u32` (per slot), `oracle/p1_builtin.u32`.

**1b. Relocation targets.** For each relocation of slot `g` in object `o`: with `sp = rel_pkg - 2147483643`,
`t = sp < 5 ? npkg + sp : rel_pkg`; if `t < npkg+5` and `base = obj_pkg[o][t] != 0xFFFFFFFF`, the target slot is
`builtin[rel_idx]` when `sp == 1`, else `base + rel_idx`; then its canonical id (1a). Otherwise 0.
Oracle: `oracle/p1_reltarget.u32` (per relocation, in `slot_rel` order).

**1c. The content-hash join** (it runs after the flood in hlink, over what the flood reached: `p1c_mark`).
Among the slots with mark 1 or 2, group kind 2 by k1, kind 3 by (k1, k2). Winner: a mark-1 copy beats a mark-2
one; then for kind 2 the largest size (k2), then the lowest id; for kind 3 the lowest id. If the winner has mark
2 the group is not in the output and nothing changes. Otherwise every member's canonical id becomes the winner,
except a mark-2 kind-2 copy larger than the winner (it keeps itself). Oracle: `oracle/p1c_canon.u32` (the
final canonical id of every slot).

**3a. Layout.** occupied(i) = size rounded up to 2^class, where a text symbol (buckets 1, 2) is at least `minFunc`
(16) bytes. For each bucket other than typelink: `va = start`; for each unit in order: if the unit has bytes in
this bucket, `va = round_up(va, max(minalign, 2^top))` with `top` its largest class with bytes; then for each class
from 12 down to 0: the class's symbols in list order get `va, va + occupied, ...`. Typelinks: sort by type string
(bytewise, then shorter first), then id; `va = start`; each gets `va = round_up(va, 2^class)` and then

**3b. Relocate.** Copy each placed symbol's bytes to `image[addr - imageBase]` (not buckets 13-15) and apply its

## Inputs, work and exclusions

[Implementation](../ref/flat/p2pipe.c) reads `oracle/p1_canon.u32` and `oracle/p1_builtin.u32`: **1a is not computed or timed**. 1b independently decodes all 9,403,582 MinIO / 19,824,324 kube relocations, including relocations of sources without CSR rows, using `slot_rel`, `slot_obj`, `obj_pkg_off`, `obj_pkg`, `rel_pkg`, `rel_idx`, then canon. It never uses `oracle/p1_reltarget.u32` to construct targets; that file is comparison-only. `obj_base`, relocation offset, size and addend are unnecessary for this plain-edge decode/filter; package bases already provide slot ids. No raw Go objects are read.

CSR sources are canonical definitions with flag 32, matching dumpflat. Weak relocations are skipped before type dispatch; METHODOFF skips its triple; USETYPE, INITORDER, USEIFACE, USEIFACEMETHOD, USENAMEDMETHOD and target zero do not produce plain relocation edges. Count and fill run in parallel, with a serial prefix over source counts. The measured fill also copies inherited edges into the new CSR. The flood is copied from p2par, with its algorithm and scheduling unchanged.

The flat CSR lacks explicit aux provenance. dumpflat emits relocations first, then funcdata aux records. Setup counts the eligible nonzero relocation targets per row; the first that-many kind-0 entries are the relocation-edge comparison set, and the remaining kind-0 entries are the inherited funcdata suffix. An assertion requires inherited funcdata to belong to text rows. Kinds 1–3, signature/name tables, flags, roots and method tables come from existing p2 files. The oracle comparison thus relies on the reviewed dumpflat ordering and relocation filter for the aux boundary; it cannot independently establish aux provenance from a separate label that the format lacks.

Excluded from all reported pipeline totals: 1a, decoding auxiliary references and special kinds, extracting method tables/interning strings, mmap/file loading, allocation, setup to isolate inherited edges, validation, and flood-state clearing/initialization. p2par also excludes its flood-state reset. Consequently this is the requested partial eager pipeline, **not a full raw-object reach implementation** or a direct replacement for dumpflat's 133–139 ms P2 conversion (which does additional work). Arrays are allocated before timing; one complete pipeline iteration warms allocated outputs and frontier storage. Nothing is read from or written to the data directories except read-only mappings.

Every pipeline invocation checks all decoded targets against `oracle/p1_reltarget.u32`; checks rebuilt kind-0 relocation destinations per source as multisets (including duplicates); checks the final materialized merged CSR per source as multisets of `(kind,destination)`; and checks sorted live ids against `oracle/p2_live.u32`. // Lazy decode flood: p2pipe's flood, but a live source's plain relocation edges are decoded from the flat relocation
// columns when it is flooded ((pkg, idx) -> slot -> canon), as hlink does on raw objects; nothing is pre-decoded.
// Funcdata aux edges, kinds 1-3 and the method tables come from the p2_* files (precomputed, untimed, as in p2pipe).
// Uses the 1a canon/builtin oracles; no 1a cost. Build: gcc -O2 -march=native -fopenmp ref/flat/p2lazy.c -o build/p2lazy
#include "flat.h"
#include <omp.h>

enum { fDef = 1, fText = 2, fReflect = 4, fGoType = 8, fIface = 16 };
static u8 *live, *iface, *ifaceDone;
static inline int tas(u8 *p) { return __atomic_exchange_n(p, 1, __ATOMIC_RELAXED) == 0; }

typedef struct { u32 *a; size_t n, cap; } vec;
static inline void push(vec *v, u32 x) {
	if (v->n == v->cap) { v->cap = v->cap ? 2 * v->cap : 4096; v->a = realloc(v->a, 4 * v->cap); }
	v->a[v->n++] = x;
}


/* dumpflat emits all relocation edges before funcdata aux edges. The first
 * nplain kind-0 entries supply the relocation-edge oracle (no aux labels exist).
 * Offsets, sizes and addends do not affect plain-edge eligibility. */

 u32 x=*(const u32 *)a, y=*(const u32 *)b; return (x>y)-(x<y);
}
static int cmp64(const void *a, const void *b) {
 u64 x=*(const u64 *)a, y=*(const u64 *)b; return (x>y)-(x<y);
}
static int plain(u16 t) {
 return !(t & 32768) && t != 22 && t != 23 && t != 24 && t != 25 && t != 26 && t != 102;
}

	const u8 *mExp = FMAP(u8, "p2_meth_exported.u8", NULL);

			rounds++;
			while (fr.n) {
				levels++;
				#pragma omp parallel
				{

					#pragma omp for schedule(dynamic, 256) nowait
					for (size_t i = 0; i < fr.n; i++) {

							}
						}
						for (u32 e = extraoff[c]; e < extraoff[c + 1]; e++) {
							u32 t = extra[e];
							switch (extrak[e]) {
							case 0:

								} else if (!live[t] && tas(&live[t])) push(nx, t);
								break;

								break;

								push(&meth[w], m);

					}
				}

				for (int w = 0; w < T; w++) {
					for (size_t k = 0; k < next[w].n; k++) push(&fr, next[w].a[k]);
					next[w].n = 0;
					for (size_t k = 0; k < meth[w].n; k++) push(&mk, meth[w].a[k]);
					meth[w].n = 0;
					reflectSeen |= refl[w];
				}
			}
			// signatures seen this round into the table, then the methods something can call
			for (u32 s = 0; s < nsig; s++) {
				if (sigSeen[s] != 1) continue;
				sigSeen[s] = 2;
				u64 k = (u64)sigName[s] << 32 | sigType[s];
				for (u64 h = mix64(k) & (hs - 1);; h = (h + 1) & (hs - 1)) {
					if (sigTab[h] == 0) { sigTab[h] = k + 1; break; }
					if (sigTab[h] == k + 1) break;
				}
			}
			size_t keep = 0;
			for (size_t i = 0; i < mk.n; i++) {
				u32 m = mk.a[i];
				int call = (reflectSeen && mExp[m]) || named[mName[m]];
				if (!call) {
					u64 k = (u64)mName[m] << 32 | mTyp[m];

				}
				if (call) {
					u32 ts[3] = {mTyp[m], mIfn[m], mTfn[m]};
					for (int d = 0; d < 3; d++) if (ts[d] && tas(&live[ts[d]])) push(&fr, ts[d]);
				} else mk.a[keep++] = m;
			}
			mk.n = keep;
			if (fr.n == 0) break;
		}
		double t1 = now();
		if (t1 - t0 < best) best = t1 - t0;
  double d=decoded-start,c=t0-decoded,f=t1-t0,t=t1-start;
  if(d<bd)bd=d;
  if(c<bc)bc=c;
  if(f<bf)bf=f;
  if(t<bt)bt=t;
	}
	nlive = 0;
	for (u32 g = 1; g < N; g++) nlive += live[g];
	u32 *list = malloc(4 * nlive), k = 0;
	for (u32 g = 1; g < N; g++) if (live[g]) list[k++] = g;
	printf("p2lazy (%d threads): lazy-decode flood best %.1f ms, %zu live, %d levels in %d rounds\n", T, best * 1e3, nlive, levels, rounds);
	
	long bad = check32("live", list, nlive, "oracle/p2_live.u32");
	printf(bad ? "P2 FAIL\n" : "P2 OK\n");
	return bad != 0;
}

// isExported: the first rune is an upper-case letter (unicode.IsUpper)
static bool isExported(str name) {
	if (name.n == 0) return false;
	u8 c = (u8)name.p[0];
	if (c < 0x80) return c >= 'A' && c <= 'Z';
	u32 r;
	int n;
	if ((c & 0xE0) == 0xC0) { r = c & 0x1F; n = 1; }
	else if ((c & 0xF0) == 0xE0) { r = c & 0x0F; n = 2; }
	else if ((c & 0xF8) == 0xF0) { r = c & 0x07; n = 3; }
	else return false;
	if (name.n < (u32)n + 1) return false;
	for (int i = 1; i <= n; i++) r = r << 6 | ((u8)name.p[i] & 0x3F);
	return iswupper((wint_t)r) != 0;
}

1. **The ~2× result is credible for these partial kernels, not end-to-end reach.** [p2pipe.c:115](/home/exedev/paradigms-w/ref/flat/p2pipe.c:115) times decoding **every relocation**, CSR count/prefix/fill—including copying inherited edges—and the flood. [p2lazy.c:116](/home/exedev/paradigms-w/ref/flat/p2lazy.c:116) times the flood with eligible plain relocations decoded on demand. They seek the same live set, but deliberately perform different intermediate work.

   Both exclude file mapping, initial allocation, state clearing, 1a resolution, extraction of columns, auxiliary/special-edge decoding, method-table construction, validation, and setup separating inherited edges. Lazy’s untimed setup itself eagerly decodes **all** targets. Frontier reallocations can still occur inside timing. Thus “2× faster than this eager implementation” is supported; “2× faster complete pipeline” is not.

2. **Lazy checks more than the final live set—but does not independently check its timed decoder.** [p2lazy.c:62](/home/exedev/paradigms-w/ref/flat/p2lazy.c:62) validates all setup-decoded targets against `oracle/p1_reltarget.u32`, then compares per-source relocation multisets, including multiplicity. Its timed decoder is separate code; only the final repetition’s live set is checked afterward. Unlike p2pipe, it has no final materialized-graph comparison.

   Consequently, a timed-loop error affecting redundant edges could pass. There is also a circularity in auxiliary extraction: the implementation’s own relocation count determines where “auxiliary” edges begin. For example, classifying zero plain relocations on text rows would let all their original kind-0 edges become inherited “aux”; the multiset comparison would compare empty lists and the text-row assertion would pass. This is a concrete weakness of the validation design, **not an observed defect in the current filter**. The actual relocation-before-aux ordering is supported by [dumpflat.c:284](/home/exedev/paradigms-w/ref/hlink/dumpflat.c:284).

3. **Eight-thread oracle success does not establish race freedom.** The shared flood uses ordinary reads of `live`/`iface` alongside atomic writes, and concurrent ordinary writes to `sigSeen`/`named`: [p2lazy.c:148](/home/exedev/paradigms-w/ref/flat/p2lazy.c:148). These are C/OpenMP data races, including when writers store the same value. This affects p2par and p2pipe too. All my runs passed, but that is narrower evidence than general parallel correctness.

4. **The hlink comparison is not equivalent work, and the caveat understates the differences.** Its flood additionally performs:

   - Raw aux-reference decoding and funcdata marking.
   - FuncInfo/inline-tree parsing and `stNameNeeded` marking of inline callees.
   - PC-table marking, including conditional handling of PC-inline tables.
   - `flRef` marking of content-addressed targets of weak/method relocations for the later hash join.
   - Itab-to-type resolution; interface-signature/name decoding; uncommon-type method-table parsing and validation.

   Evidence: [dead.c:301](/home/exedev/paradigms-w/ref/hlink/dead.c:301), [dead.c:369](/home/exedev/paradigms-w/ref/hlink/dead.c:369), [dead.c:411](/home/exedev/paradigms-w/ref/hlink/dead.c:411), [dead.c:580](/home/exedev/paradigms-w/ref/hlink/dead.c:580). Some work is precomputed for lazy; other outputs are absent entirely. Merely decoding aux and special kinds lazily would **not** make the comparison exact.

   There is an opposite timing mismatch too: hlink’s quoted `floods` timer surrounds parallel flood tasks, excluding frontier merging and separately timed method processing ([dead.c:759](/home/exedev/paradigms-w/ref/hlink/dead.c:759)). Lazy includes both. [GRID.md:24](/home/exedev/paradigms-w/GRID.md:24) explicitly lists an additional **7 / 1.5 ms** for hlink methods. Hash joining and publication are also separate; they should not be charged to its quoted flood. The net fair speedup cannot be recovered from these numbers.
